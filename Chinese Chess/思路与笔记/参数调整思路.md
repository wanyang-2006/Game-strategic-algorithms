# 参数表及分析

下面按“ **真正需要调参的评价参数** ”和“ **程序运行/搜索/规则常量** ”两大类整理。重点是：当前程序的参数并不只在 `TuningParams.h` 中，很多评估表和权重直接写在 `Chinese_Chess_trial_1.cpp` 里。

## 1. 棋盘、棋子、规则类基础参数

这些一般不建议调，只是程序规则和坐标系统的一部分。

| 参数              |                                                                        当前值 | 作用                | 是否建议调 |
| ----------------- | ----------------------------------------------------------------------------: | ------------------- | ---------- |
| `BOARDWIDTH`    |                                                                         `9` | 棋盘宽度            | 否         |
| `BOARDHEIGHT`   |                                                                        `10` | 棋盘高度            | 否         |
| `baseLine[2]`   |                                                                    `{9, 0}` | 红黑双方底线 y 坐标 | 否         |
| `stoneSym`      |                                                                `"*kbnrpca"` | 棋子字符映射        | 否         |
| `stoneType`枚举 | `None=0, King=1, Bishop=2, Knight=3, Rook=4, Pawn=5, Cannon=6, Assistant=7` | 棋子类型编号        | 否         |
| `colorType`枚举 |                                                   `BLACK=0, RED=1, EMPTY=2` | 棋子颜色编号        | 否         |

这些定义在程序开头，确定了 9×10 棋盘、棋子类型编号和红黑颜色编号。

## 2. 着法生成方向参数

这些是棋子走法的方向数组，属于规则参数，不是评价参数。

| 参数                                      | 当前值/长度 | 作用               |
| ----------------------------------------- | ----------: | ------------------ |
| `dx[]`,`dy[]`                         |      8 方向 | 通用八方向偏移     |
| `dx_ob[]`,`dy_ob[]`                   |      4 方向 | 士/仕斜向移动      |
| `dx_strai[]`,`dy_strai[]`             |      4 方向 | 车/炮/将帅直线方向 |
| `dx_lr[]`                               |      2 方向 | 兵卒过河后左右移动 |
| `dx_knight[]`,`dy_knight[]`           |      8 方向 | 马的目标格         |
| `dx_knight_foot[]`,`dy_knight_foot[]` |      8 方向 | 马腿检测点         |
| `dx_bishop[]`,`dy_bishop[]`           |      4 方向 | 象/相目标格        |
| `dx_bishop_eye[]`,`dy_bishop_eye[]`   |      4 方向 | 象眼检测点         |

这些参数直接决定棋规，不能当作棋力调参对象。

## 3. Zobrist 与置换表参数

| 参数                       |               当前值 | 作用                             | 是否可调         |
| -------------------------- | -------------------: | -------------------------------- | ---------------- |
| `ZobristTable[8][2][90]` |           运行时生成 | 每种棋子、颜色、位置的哈希随机数 | 否               |
| `ZobristPlayer`          |           运行时生成 | 标识当前轮到谁走棋               | 否               |
| Zobrist 随机种子           |      `20262026ULL` | 固定生成 Zobrist 表，保证复现    | 一般不调         |
| `TT_SIZE`                |          `1048576` | 置换表大小，1M 项                | 可作为性能参数调 |
| `HashFlag`               | `EXACT/ALPHA/BETA` | 置换表节点类型                   | 否               |

`TT_SIZE` 是比较重要的工程参数，影响内存占用和置换表命中率；Zobrist 随机种子不影响棋力，只影响哈希分布和复现性。

## 4. 时间控制参数

| 参数                               |    当前值 | 作用                   | 是否可调 |
| ---------------------------------- | --------: | ---------------------- | -------- |
| `SearchTime(int limit_ms = 900)` | `900ms` | 单步默认搜索时间上限   | 是       |
| `checkerCount % 1024`            |  `1024` | 每 1024 次检查一次时间 | 可调     |
| `ChessAI(..., searchTime(900))`  | `900ms` | AI 构造时固定时间限制  | 是       |

这类参数影响 Botzone 超时风险和搜索深度。`900ms` 是比较保守的单步时间限制，若平台允许更长时间，可以尝试提高；但要配合超时兜底统计。

## 5. 静态子力表参数：核心评价参数

这是当前程序中最重要的一组参数。每张表都是 `90` 个整数，对应 9×10 棋盘位置价值。代码注释说明这些表“均为对红方而言的数据”，红黑使用时通过坐标翻转或不同索引访问。

### 5.1 帅/兵位置表

| 表名                           | 阶段 | 条件       | 维度 | 用途                        |
| ------------------------------ | ---- | ---------- | ---: | --------------------------- |
| `mid_KingPawn_attack[90]`    | 中局 | 有进攻机会 |   90 | 兵/帅有攻击机会时的位置价值 |
| `mid_KingPawn_no_attack[90]` | 中局 | 无进攻机会 |   90 | 兵/帅无攻击机会时的位置价值 |
| `end_KingPawn_attack[90]`    | 残局 | 有进攻机会 |   90 | 残局兵/帅进攻价值           |
| `end_KingPawn_no_attack[90]` | 残局 | 无进攻机会 |   90 | 残局兵/帅普通位置价值       |

程序在评估 `Pawn` 和 `King` 时，会先调用 `hasattackchance(x,y)` 判断是否有吃子/攻击机会，再选择 attack 或 no_attack 表。

### 5.2 士/象位置表

| 表名                         | 条件     | 维度 | 用途                  |
| ---------------------------- | -------- | ---: | --------------------- |
| `mid_AdvBis_no_Threat[90]` | 未受威胁 |   90 | 士/象安全时位置价值   |
| `mid_AdvBis_Threat[90]`    | 受威胁   |   90 | 士/象被攻击时位置价值 |

注意：当前代码中士/象在 **中局和残局都使用这两张 `mid_AdvBis_*` 表** ，没有单独的残局士象表。程序通过 `isattacked(oppCol, x, y)` 判断士/象是否受威胁。

### 5.3 马位置表

| 表名              | 阶段 | 维度 | 用途             |
| ----------------- | ---- | ---: | ---------------- |
| `mid_horse[90]` | 中局 |   90 | 马的中局位置价值 |
| `end_horse[90]` | 残局 |   90 | 马的残局位置价值 |

马在中局用 `mid_horse`，残局用 `end_horse`。

### 5.4 车位置表

| 表名             | 阶段 | 维度 | 用途             |
| ---------------- | ---- | ---: | ---------------- |
| `mid_Rook[90]` | 中局 |   90 | 车的中局位置价值 |
| `end_Rook[90]` | 残局 |   90 | 车的残局位置价值 |

车在中局用 `mid_Rook`，残局用 `end_Rook`。

### 5.5 炮位置表

| 表名               | 阶段 | 维度 | 用途             |
| ------------------ | ---- | ---: | ---------------- |
| `mid_Cannon[90]` | 中局 |   90 | 炮的中局位置价值 |
| `end_Cannon[90]` | 残局 |   90 | 炮的残局位置价值 |

炮在中局用 `mid_Cannon`，残局用 `end_Cannon`。

## 6. 中局/残局阶段判断参数

| 参数                  |                    当前值 | 作用                         | 是否建议调 |
| --------------------- | ------------------------: | ---------------------------- | ---------- |
| `Rook_state`        |                     `6` | 每个车对阶段值的贡献         |            |
| `HorseCannon_state` |                     `3` | 每个马/炮对阶段值的贡献      |            |
| `other_state`       |                     `1` | 其它棋子的阶段贡献           |            |
| `Total_state`       |                    `66` | 阶段总量阈值参考             |            |
| 判断条件              | `tmp > Total_state / 2` | 大于一半判定为中局，否则残局 |            |

这一组参数决定当前局面使用“中局表”还是“残局表”。当前实现是硬切换，不是平滑插值。

需要注意一个问题：`ismiddlecompostion()` 的 `else` 分支会让非车、非马炮的所有格子都加 `other_state`，包括空格。这会让阶段判断偏高，建议后续修正为“只对非空棋子加分”。

## 7. 动态控制点评估参数

这一组用于 `caldynamicstate()`，根据棋盘控制点在不同区域加分。

| 参数              | 当前值 | 含义                   |
| ----------------- | -----: | ---------------------- |
| `EnemyKingArea` |  `8` | 控制敌方九宫的加分     |
| `EnemyHalf`     |  `5` | 控制敌方半场的加分     |
| `OwnHalf`       |  `2` | 控制己方半场的防御加分 |
| `OwnKingArea`   |  `3` | 控制己方九宫的防御加分 |
| `attackweight`  |  `1` | 进攻项总权重           |
| `defenceweight` |  `1` | 防御项总权重           |

动态评估最终形式为：

```cpp
res = attackweight * (myattack - oppattack)
    + defenceweight * (myDefense - oppDefence);
```

这类参数非常适合后续自动调参。

## 8. 总评估权重参数

代码中定义了四个总评估权重：

| 参数                 | 当前值 | 设计含义         |
| -------------------- | -----: | ---------------- |
| `mystaticweight`   |  `1` | 我方静态评估权重 |
| `mydynamicweight`  |  `1` | 我方动态评估权重 |
| `oppstaticweight`  |  `1` | 对方静态评估权重 |
| `oppdynamicweight` |  `1` | 对方动态评估权重 |

但当前 `calstate()` 实际只做了：

```cpp
res += calstaticstate(target, color);
res += caldynamicstate(target, color);
```

也就是说，这四个权重 **目前没有真正参与计算** 。它们是“预留参数”，不是有效参数。

## 9. MVV-LVA 着法排序参数：`TuningParams.h`

`TuningParams.h` 中定义的是吃子着法排序参数，不是局面静态价值本身。

| 参数                       |    当前值 | 作用                         |
| -------------------------- | --------: | ---------------------------- |
| `VictimValue[None]`      |     `0` | 被吃空子无价值               |
| `VictimValue[King]`      | `10000` | 被吃将/帅价值                |
| `VictimValue[Bishop]`    |   `200` | 被吃象/相价值                |
| `VictimValue[Knight]`    |   `400` | 被吃马价值                   |
| `VictimValue[Rook]`      |   `900` | 被吃车价值                   |
| `VictimValue[Pawn]`      |   `100` | 被吃兵/卒价值                |
| `VictimValue[Cannon]`    |   `450` | 被吃炮价值                   |
| `VictimValue[Assistant]` |   `200` | 被吃士/仕价值                |
| `AttackerValue[...]`     |      同上 | 攻击方棋子价值               |
| `CaptureBaseScore`       | `10000` | 保证吃子着法优先于非吃子着法 |

MVV-LVA 分数公式是：

```cpp
CaptureBaseScore + VictimValue[victim] * 10 - AttackerValue[attacker]
```

也就是说，“吃高价值子、用低价值子吃”会排得更靠前。

在静态搜索里，吃子着法还会额外加 `100000`：

```cpp
node.value = Tuning::getMVVLVAScore(attacker, victim) + 100000;
```

这进一步确保静态搜索优先扩展吃子着法。

## 10. 搜索边界与剪枝参数

| 参数                       |                              当前值 | 作用                                                              |
| -------------------------- | ----------------------------------: | ----------------------------------------------------------------- |
| 全局 `max_depth`         |                              `64` | 杀手着法表数组维度上限                                            |
| 搜索入口局部 `max_depth` |                              `10` | `alpha_beta_select()`和 `alpha_beta_PVS_select()`实际搜索深度 |
| `minstateval`            |                        `-9999999` | alpha 初始下界                                                    |
| `maxstateval`            |                         `9999999` | beta 初始上界                                                     |
| `getWin()`返回           |                          `999999` | 搜索中发现胜利时的返回值                                          |
| 无合法步惩罚               | `minstateval + 100 * (4 - depth)` | 被将死/无路可走时的返回值                                         |
| 静态搜索被将死惩罚         |              `minstateval + 1000` | 静态搜索中被将死时返回                                            |
| Null Move Reduction `R`  |                               `2` | 空步裁剪深度缩减                                                  |
| LMR `R`                  |                               `1` | Late Move Reduction 对 quiet move 的缩减深度                      |
| LMR 触发深度               |                      `depth >= 3` | 深度至少 3 才做 LMR                                               |
| 杀手着法数                 |                        每层 `2`个 | `killerMoves[depth][0/1]`                                       |

其中真正影响棋力和速度的，是局部搜索深度 `10`、空步裁剪 `R=2`、LMR `R=1`、时间限制 `900ms`、以及置换表大小 `TT_SIZE`。

# 汇总：真正建议优先调的参数

按优先级看，当前程序最值得调的是：

1. **静态子力表**
   `mid_KingPawn_attack/no_attack`、`end_KingPawn_attack/no_attack`、`mid_AdvBis_Threat/no_Threat`、`mid_horse/end_horse`、`mid_Rook/end_Rook`、`mid_Cannon/end_Cannon`。 (已经调整为Botzone中的参数)
2. **中局/残局阶段参数**
   `Rook_state = 6`、`HorseCannon_state = 3`、`other_state = 1`、`Total_state = 66`。(已经调整为Botzone中的参数)
3. **动态控制点参数**
   `EnemyKingArea = 8`、`EnemyHalf = 5`、`OwnHalf = 2`、`OwnKingArea = 3`、`attackweight = 1`、`defenceweight = 1`。
4. **MVV-LVA 着法排序参数**
   `VictimValue[]`、`AttackerValue[]`、`CaptureBaseScore = 10000`。
5. **搜索效率参数**
   `max_depth = 10`、`R = 2` 空步裁剪、`R = 1` LMR、`TT_SIZE = 1048576`、`timeLimit_ms = 900`、静态搜索吃子加成 `+100000`。

其中，`mystaticweight/mydynamicweight/oppstaticweight/oppdynamicweight` 虽然已经定义，但当前没有被真正用于 `calstate()`，暂时不能算有效参数。
