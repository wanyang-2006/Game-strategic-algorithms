# 中国象棋 Botzone 评测程序流程与架构图

本程序以无状态回合机制为基础，依赖重放全局历史步来还原棋盘状态并进行后续博弈。以下是程序中核心流程以及数据结构的图解分析：

## 一、 程序整体运行流程图 
整个程序的运行从 `main()` 开始，读取平台给定的 JSON 历史交互数组，通过步步重演恢复当前战局，并生成应答步。

```mermaid
graph TD
    A([程序启动 main]) --> B[初始化 Chess 对象]
    B --> C[调用 getInputBotzone 处理输入]
    
    subgraph Phase1 [状态还原阶段]
        D[解析JSON获取requests和responses数组]
        E{遍历所有的历史回合}
        F[解析起始与目标坐标构建 Move 对象]
        G[isMoveValidWithForbidden 验证移动否打破规定]
        H[makeMoveAssumeLegal 执行该步更新棋盘]
    end
    
    C --> D
    D --> E
    E -- 取出历史步 --> F
    F --> G
    G --> H
    H --> E
    
    E -- 历史回合遍历结束 --> I[读取本回合最新 request 并落子]
    I --> J[调用 giveOutputBotzone 生成我方决策]
    
    subgraph Phase2 [决策与输出阶段]
        K[调用 generateMovesWithForbidden]
        L[获取包含所有符合规则的可用 Move 集合]
        M{是否无路可走}
        N[输出认输]
        O[随机选取一步 Move]
        P[格式化为标准 PGN 坐标如h2e2]
        Q[包装为 JSON 输出]
    end
    
    J --> K
    K --> L
    L --> M
    M -- 是 --> N
    M -- 否 --> O
    O --> P
    P --> Q
    
    Q --> R([程序结束])
    N --> R
```

## 二、 生成着法与禁手检测流程图
本部分详细展开 `generateMovesWithForbidden()` 内部校验合法性、防御送将与长将禁手规则逻辑的过程，这也是象棋规则引擎最复杂的部分。

```mermaid
graph TD
    A([调用 generateMovesWithForbidden]) --> B[调用 generateMoves 生成常规合法步]
    
    subgraph Sub1 [常规合法步生成规则 generateMoves]
        C{嵌套循环遍历棋盘}
        D[根据枚举类型判断行动逻辑]
        E[取对应 dx dy 或其他规则衍生目标点]
        F{目标点合法且非己方棋子}
        G{mustDefend等于true}
        H[调用 isMyKingAttackedAfterMove 检测是否送将]
        I[makeMoveAssumeLegal 假设落子]
        J[attacked 检查老帅受击]
        K[undoMove 撤销回退]
        M[存入常规合法步列表]
    end
    
    B --> C
    C -- 遇到己方棋子 --> D
    D --> E
    E --> F
    F -- 非法 --> C
    F -- 验证通过 --> G
    
    G -- 是 --> H
    H --> I
    I --> J
    J --> K
    K -- 被将军 --> C
    K -- 安全 --> M
    G -- 否直接存入 --> M
    M --> N{常规遍历完成}
    
    N -- 否 --> C
    N -- 是 --> O{遍历已生成的 Move}
    
    subgraph Sub2 [禁手规则校验]
        P[调用 repeatAfterMove]
        Q[makeMoveAssumeLegal 假设走子]
        R[向历史状态回溯比对当前 state]
        S[undoMove 撤销回退]
        T[存入最终合规集合]
    end
    
    O -- 处理单个 Move --> P
    P --> Q
    Q --> R
    R --> S
    S -- 出现三次重复局面 --> O
    S -- 无违规 --> T
    
    T --> U{排查结束}
    U -- 否 --> O
    U -- 是 --> V([返回 legalMoves 向量])
```

## 三、 数据结构与类间关系图
程序的底层由几个核心结构来支撑，主要围绕全局对象 `Chess` 的成员状态及其函数划分。

```mermaid
classDiagram
    class Move {
        <<struct>>
        +int source_x
        +int source_y
        +int target_x
        +int target_y
    }

    class Grid {
        <<struct>>
        +stoneType type
        +colorType color
    }

    class stoneType {
        <<enumeration>>
        None
        King
        Bishop
        Knight
        Rook
        Pawn
        Cannon
        Assistant
    }
    
    class colorType {
        <<enumeration>>
        BLACK
        RED
        EMPTY
    }

    class Chess {
        -vector_Grid_state
        -int currTurnId
        +resetBoard()
        +makeMoveAssumeLegal() bool
        +undoMove()
        +generateMoves()
        +generateMovesWithForbidden()
        +attacked() bool
        +repeatAfterMove() bool
        +isMyKingAttackedAfterMove() bool
        +betweenIsEmpty() bool
        +exceedMaxPeaceState() bool
    }

    Chess "1" *-- "*" Grid : 包含状态
    Chess ..> Move : 生成
    Grid --> stoneType : 具有
    Grid --> colorType : 具有
```
