# 迭代加深搜索与置换表

## 一、概述

在博弈树搜索中，**迭代加深搜索（Iterative Deepening）** 和**置换表（Transposition Table）** 是两项极为重要的优化技术。它们与 Alpha-Beta 剪枝配合使用，构成了几乎所有经典棋类 AI 引擎的核心框架。

---

## 二、迭代加深搜索（Iterative Deepening Depth-First Search, IDDFS）

### 1. 基本思想

迭代加深搜索以**逐步增加搜索深度**的方式运行：先搜索 1 层，再搜索 2 层，再搜索 3 层……直到时间用尽或达到目标深度。

```
for depth = 1, 2, 3, ..., maxDepth:
    result = alphaBeta(root, depth, -∞, +∞)
    if time is up:
        break
return result
```

### 2. 为什么要"重复搜索"？

乍看之下，每次加深都重复搜索之前的层级，似乎很浪费。但实际上：

**时间开销很小：** 由于博弈树的节点数随深度呈指数增长（$b^d$），最后一层的搜索量占总搜索量的绝大部分。重复搜索前面的浅层，额外开销通常不超过总搜索时间的 10-15%。

假设分支因子 $b = 35$（国际象棋），搜索 $d$ 层的节点数为 $35^d$：

| 深度 | 节点数 | 占比 |
|:---:|:---:|:---:|
| 1 | 35 | 0.003% |
| 2 | 1,225 | 0.08% |
| 3 | 42,875 | 2.9% |
| 4 | 1,500,625 | 97% |

### 3. 迭代加深的优势

1. **自然的时间管理**：可以在任何时刻中断搜索，返回当前最优结果
2. **改善节点排序**：浅层搜索的结果可以用于深层搜索的节点排序，极大提升 Alpha-Beta 的剪枝效率
3. **渐进式结果**：随着搜索加深，结果逐渐精确，用户可以看到搜索进度
4. **结合深度优先的内存效率**：不需要像广度优先搜索那样存储整层节点

### 4. 伪代码

```
function iterativeDeepening(rootState, timeLimit):
    bestMove = null

    for depth = 1 to MAX_DEPTH:
        currentBest = alphaBetaRoot(rootState, depth)
        bestMove = currentBest

        if elapsed_time > timeLimit:
            break

    return bestMove


function alphaBetaRoot(state, depth):
    bestMove = null
    bestScore = -∞
    alpha = -∞
    beta = +∞

    // 使用上一轮的最优走法优先搜索
    moves = generateMoves(state)
    orderMoves(moves, previousBestMove)

    for each move in moves:
        newState = apply(state, move)
        score = -alphaBeta(newState, depth - 1, -beta, -alpha)

        if score > bestScore:
            bestScore = score
            bestMove = move

        alpha = max(alpha, score)

    return bestMove
```

## 三、置换表（Transposition Table）

### 1. 什么是置换

在博弈树中，不同的走法序列可能到达**完全相同的局面**。例如在国际象棋中：

```
1. e4 e5 2. Nf3   和   1. Nf3 e5 2. e4
```

这两个不同的走法顺序达到了同一个局面。如果不做任何优化，搜索引擎会对同一个局面重复计算，造成极大的浪费。

### 2. 置换表的作用

置换表是一个**哈希表**，用于存储已经搜索过的局面及其评估结果。当搜索遇到相同局面时，可以直接查表获取结果，避免重复搜索。

### 3. Zobrist 哈希

**Zobrist 哈希** 是棋类 AI 中最常用的局面哈希方法，由 Albert Zobrist 于 1970 年提出。

**初始化：** 为每种棋子在每个位置预先生成一个随机的 64 位整数。

```cpp
// 以国际象棋为例
uint64_t zobristTable[12][64];  // 12种棋子 × 64个格子
uint64_t zobristSide;            // 表示轮到谁走的随机数

void initZobrist() {
    std::mt19937_64 rng(42);
    for (int piece = 0; piece < 12; piece++)
        for (int square = 0; square < 64; square++)
            zobristTable[piece][square] = rng();
    zobristSide = rng();
}
```

**计算哈希值：** 对局面中所有棋子的哈希值做异或：

$$\text{hash} = \bigoplus_{(piece, square) \in \text{board}} \text{zobristTable}[piece][square]$$

**增量更新：** 移动棋子时，只需异或变化的部分：

```cpp
// 将 piece 从 fromSq 移到 toSq
hash ^= zobristTable[piece][fromSq];   // 移除旧位置
hash ^= zobristTable[piece][toSq];     // 添加新位置
hash ^= zobristSide;                    // 切换行棋方
```

Zobrist 哈希的关键优势：**增量更新只需常数时间**，不需要重新计算整个局面的哈希。

### 4. 置换表条目结构

```cpp
enum TTFlag {
    EXACT,       // 精确值
    LOWER_BOUND, // α 截断（搜索值 ≥ β，实际值可能更大）
    UPPER_BOUND  // β 截断（搜索值 ≤ α，实际值可能更小）
};

struct TTEntry {
    uint64_t key;     // Zobrist 哈希值（或其一部分，用于验证）
    int depth;        // 搜索深度
    int score;        // 评估分数
    TTFlag flag;      // 分数类型
    int bestMove;     // 最佳走法（用于节点排序）
};

// 置换表（使用数组 + 哈希索引）
const int TT_SIZE = 1 << 20;  // 约 100万 个条目
TTEntry transpositionTable[TT_SIZE];
```

### 5. 在 Alpha-Beta 中使用置换表

```cpp
int alphaBeta(GameState state, int depth, int alpha, int beta) {
    uint64_t hash = state.zobristHash();
    int index = hash % TT_SIZE;

    // 1. 查表
    TTEntry& entry = transpositionTable[index];
    if (entry.key == hash && entry.depth >= depth) {
        if (entry.flag == EXACT) return entry.score;
        if (entry.flag == LOWER_BOUND) alpha = std::max(alpha, entry.score);
        if (entry.flag == UPPER_BOUND) beta = std::min(beta, entry.score);
        if (alpha >= beta) return entry.score;
    }

    // 2. 终止条件
    if (depth == 0 || state.isTerminal()) {
        return evaluate(state);
    }

    // 3. 正常搜索
    int bestScore = -INF;
    auto moves = state.generateMoves();

    // 使用置换表中的最佳走法优先搜索
    if (entry.key == hash) {
        orderMoveFirst(moves, entry.bestMove);
    }

    int bestMove = moves[0];
    for (auto& move : moves) {
        state.makeMove(move);
        int score = -alphaBeta(state, depth - 1, -beta, -alpha);
        state.undoMove(move);

        if (score > bestScore) {
            bestScore = score;
            bestMove = move;
        }
        alpha = std::max(alpha, score);
        if (alpha >= beta) break;
    }

    // 4. 存表
    TTEntry newEntry;
    newEntry.key = hash;
    newEntry.depth = depth;
    newEntry.score = bestScore;
    newEntry.bestMove = bestMove;
    if (bestScore <= alpha) newEntry.flag = UPPER_BOUND;
    else if (bestScore >= beta) newEntry.flag = LOWER_BOUND;
    else newEntry.flag = EXACT;
    transpositionTable[index] = newEntry;

    return bestScore;
}
```

## 四、其他重要优化技术

### 1. 杀手启发（Killer Heuristic）

记录在同一深度导致 Beta 截断的走法（"杀手走法"），在兄弟节点中优先搜索。

```cpp
int killerMoves[MAX_DEPTH][2];  // 每层记录两个杀手走法
```

### 2. 历史启发（History Heuristic）

为每种走法维护一个历史分数——该走法在过去的搜索中导致截断的次数越多，分数越高。

```cpp
int historyTable[64][64];  // [fromSquare][toSquare]

// 发生截断时更新
historyTable[from][to] += depth * depth;
```

### 3. 空着搜索（Null Move Pruning）

假设当前方"跳过"一步（什么都不做），如果对手在这种优势下仍然无法获得好结果，则当前局面肯定很好，可以进行截断。

```
if depth >= 3 and not in check:
    make null move
    score = -alphaBeta(depth - 1 - R, -beta, -beta + 1)
    undo null move
    if score >= beta:
        return beta  // 截断
```

$R$ 通常取 2 或 3（减少搜索深度）。

### 4. 渴望窗口（Aspiration Window）

在迭代加深中，利用上一次迭代的结果设置较窄的初始搜索窗口 $[\alpha, \beta]$：

```
value = previousScore
alpha = value - WINDOW
beta = value + WINDOW

score = alphaBeta(root, depth, alpha, beta)

if score <= alpha or score >= beta:
    // 窗口失败，用完整窗口重搜
    score = alphaBeta(root, depth, -INF, +INF)
```

窗口越窄，剪枝越多；但如果实际值超出窗口，需要重新搜索。

### 5. 静态搜索（Quiescence Search）

在搜索达到最大深度时，不直接返回评估值，而是继续搜索"不稳定"的走法（如吃子、将军），直到局面"安静"下来再评估。这避免了**水平线效应**（horizon effect）——即在搜索截止点恰好面临重大变化导致的评估失真。

```
function quiescenceSearch(state, alpha, beta):
    standPat = evaluate(state)
    if standPat >= beta:
        return beta
    alpha = max(alpha, standPat)

    for each capture move:
        state.makeMove(move)
        score = -quiescenceSearch(state, -beta, -alpha)
        state.undoMove(move)

        if score >= beta:
            return beta
        alpha = max(alpha, score)

    return alpha
```

## 五、完整搜索框架

将以上技术组合，一个典型的棋类 AI 搜索框架如下：

```
1. 迭代加深循环 (Iterative Deepening)
   └─ 2. 渴望窗口 (Aspiration Window)
       └─ 3. Alpha-Beta 搜索 (带 Negamax 框架)
           ├─ 3a. 查询置换表 (Transposition Table Probe)
           ├─ 3b. 空着搜索 (Null Move Pruning)
           ├─ 3c. 走法排序 (Move Ordering)
           │    ├─ 置换表最佳走法
           │    ├─ 杀手启发
           │    └─ 历史启发
           ├─ 3d. PVS 搜索 (Principal Variation Search)
           ├─ 3e. 存入置换表
           └─ 3f. 静态搜索 (Quiescence Search, 到达叶节点时)
```

## 六、性能对比

以国际象棋中盘局面为例（分支因子 ≈ 35）：

| 技术组合 | 等效搜索深度提升 |
|:---:|:---:|
| 纯 Minimax | 基准 |
| + Alpha-Beta | 约 ×2 |
| + 迭代加深 + 节点排序 | 约 ×2.5 |
| + 置换表 | 约 ×3 |
| + 空着搜索 | 约 ×4 |
| + 静态搜索 | 评估质量大幅提升 |

---

## 七、总结

| 技术 | 核心作用 |
|:---:|:---:|
| 迭代加深 | 时间管理 + 改善节点排序 |
| 置换表 | 避免重复搜索 + 提供最佳走法 |
| Zobrist 哈希 | 快速局面哈希 + 增量更新 |
| 杀手/历史启发 | 改善走法排序 → 更多剪枝 |
| 空着搜索 | 大幅减少搜索节点 |
| 静态搜索 | 消除水平线效应 |

这些技术相互配合，使得棋类 AI 能够在有限的时间和内存下，达到极深的搜索深度和极高的对弈水平。现代国际象棋引擎（如 Stockfish）正是这些技术的集大成者。
