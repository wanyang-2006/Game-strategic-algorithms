结论：**一上来吃子是搜索/估值策略导致的“合法但很短视”的炮打马；三回合后 INVALID_INPUT_VERDICT 则是程序在重放历史输入时抛异常退出，Botzone 没拿到合法 JSON 输出。**

## 1. 为什么双方一上来就吃子？

这不是开局库缺失直接造成的非法行为，而是你的程序会优先选择“炮打马”这类吃子步。

初始局面里：

红炮在 `b2`，黑马在 `b9`，中间有黑炮 `b7` 作为炮架，所以 `b2 -> b9` 是合法炮吃马。黑方同理，黑炮 `h7` 可以隔着红炮 `h2` 吃红马 `h0`。你的 `resetBoard()` 正是这样摆子的：红炮在 `(1,2)/(7,2)`，黑炮在 `(1,7)/(7,7)`，红马在 `(1,0)/(7,0)`，黑马在 `(1,9)/(7,9)`。

而炮的走法生成逻辑明确允许“中间恰好一个棋子，目标为对方棋子”时加入合法着法。

更关键的是，你的着法排序把吃子步强行排到非吃子步前面：`CaptureBaseScore = 100`，而非吃子在 `calcurmove()` 里直接返回 `0`。 后面 `fill_sort_inMoveNodes()` 又按这个分数降序排序。

所以在无开局库、900ms 限时、10 层搜索很容易超时或只完成很浅评估的情况下，根节点最前面的就是“炮吃马”。这解释了截图中双方一开始互相炮打马的现象。

## 2. 为什么三个回合后出现输入不合法？

从代码看，`INVALID_INPUT_VERDICT` 很可能不是 Botzone 先判定某一步“走法非法”，而是你的程序在 `getInputBotzone()` 重放历史时自己抛出了：

```cpp
throw std::runtime_error("input is not valid!");
```

`getInputBotzone()` 会把历史 `requests` 和 `responses` 逐步重放，并且每一步都调用 `chess.isMoveValidWithForbidden(curMove)` 检查。只要某一步在你本地棋盘状态里不合法，就直接抛异常。 但 `main()` 没有捕获这个异常，直接退出，Botzone 就会看到“没有合法输出/输出异常”，于是给 `INVALID_INPUT_VERDICT`。

这里有几个高概率诱因：

**第一，程序算出了 `currBotColor` 但完全没用。** 代码根据第一条 request 判断自己是红还是黑，但后面没有用它做任何校验、坐标转换或当前行棋方检查。 如果 Botzone 的黑方输入坐标是相对黑方视角，或者你的本地坐标系与平台协议有一处不一致，到第三回合重放历史时就会出现“平台认为合法、你的程序认为非法”。

**第二，搜索里有一个实际的空步回撤风险。** 在 `alpha_beta_PVS_search()` 里直接 `MoveNodeVoid()`，递归后再手动 `undoNullMove()`。如果递归中抛出超时异常，`undoNullMove()` 不会执行，搜索用的棋盘会残留一个空步。 这会让搜索结果和真实棋盘脱节，虽然输出前你又在原棋盘上验证了一次，但它会让选择过程非常不稳定，增加走出奇怪步、触发 fallback 或后续重放不一致的概率。

**第三，局面评估没有刷新控制表。** `calstate()` 直接调用 `calstaticstate()` 和 `caldynamicstate()`，但没有先调用 `getGridcontrol()`；而 `caldynamicstate()` 依赖 `GridControl`，`hasattackchance()` 依赖 `havecontrol`。 这会导致评估退化，进一步让程序更依赖吃子排序，而不是稳定的局面判断。

## 建议优先改这几处

先在 `getInputBotzone()` 里打印到底是哪一步非法：

```cpp
if (!chess.isMoveValidWithForbidden(curMove)) {
    std::cerr << "invalid at request[" << i << "]: "
              << curSource << " -> " << curTarget
              << ", currTurnId=" << chess.currTurnId << std::endl;
    throw std::runtime_error("input is not valid!");
}
```

然后把 `main()` 包一层 `try/catch`，至少让 Botzone 上能看到 stderr 调试信息：

```cpp
int main() {
    try {
        InitZobrist();
        Chess chess;
        getInputBotzone(chess);
        giveOutputBotzone(chess);
    } catch (const std::exception& e) {
        std::cerr << "FATAL: " << e.what() << std::endl;
        return 1;
    }
}
```

搜索部分建议把空步改成 RAII，避免异常时不回撤：

```cpp
if (depth >= R + 1 && !havethreat(board->state[board->currTurnId], board->currColor)) {
    NullMoveGuard guard(this);
    int null_val = -alpha_beta_PVS_search(depth - 1 - R, -beta, -beta + 1);
    if (null_val >= beta) return beta;
}
```

最后，如果你只是想避免开局互吃，把根节点前几回合的“炮吃马”加惩罚，或者恢复开局库；否则在当前 MVV/LVA 排序下，`炮二进七吃马`、`炮八进七吃马` 这类步会天然排在最前面。
