# GPT5.5 Pro

你追问的这句话，核心不是说“Botzone 给你的 JSON 输入非法”，而是说：**你的程序在解析并重放 Botzone 已经给出的历史着法时，自己判定某一步“不合法”，随后抛出异常；这个异常没有被 `main()` 捕获，进程直接退出，导致 Botzone 没收到一条合法 JSON 输出，于是显示 `INVALID_INPUT_VERDICT` 或类似的非法判定。**

## 1. 为什么 `getInputBotzone()` 中的异常会导致 Botzone 判非法？

你现在的主函数是：

```cpp
int main()
{
    InitZobrist();
    Chess chess;
    getInputBotzone(chess);
    giveOutputBotzone(chess);
    return 0;
}
```

也就是先恢复棋盘，再输出着法。这里没有任何 `try/catch`。如果 `getInputBotzone(chess)` 里面抛出 `std::runtime_error`，程序会直接终止，根本执行不到 `giveOutputBotzone(chess)`。你的 `giveOutputBotzone()` 里面虽然对 AI 搜索做了 `try/catch`，但这个保护范围只在输出阶段，保护不到输入解析阶段。

而 `getInputBotzone()` 里面确实对历史每一步都做了强校验。例如历史 `requests[i]`：

```cpp
Move curMove(curSource, curTarget);
if (!chess.isMoveValidWithForbidden(curMove))
{
    throw std::runtime_error("input is not valid!");
}
chess.makeMoveAssumeLegal(curMove);
```

历史 `responses[i]` 和当前 `requests[turnID]` 也是同样逻辑。只要其中任何一步在你本地棋盘上不通过 `isMoveValidWithForbidden()`，就直接 `throw`。

Botzone 对 Bot 的基本要求是：本轮运行结束时，程序必须向标准输出输出一个合法 JSON，例如：

```json
{"response":{"source":"b2","target":"b9"}}
```

如果你的程序在 `getInputBotzone()` 中异常退出，那么标准输出可能是空的，或者没有 `response.source/response.target`。从平台角度看，这就等价于“Bot 没有给出合法输出”。所以它显示 `INVALID_INPUT_VERDICT`，并不一定意味着平台传给你的输入 JSON 本身错了。

## 2. 为什么 `isMoveValidWithForbidden()` 容易在重放历史时误杀？

你在输入阶段使用的是：

```cpp
chess.isMoveValidWithForbidden(curMove)
```

这个函数不是单纯检查“这个棋子能不能这么走”，而是会调用：

```cpp
generateMovesWithForbidden(...)
```

然后 `generateMovesWithForbidden()` 又会调用 `repeatAfterMove()` 排除重复局面、长打等规则相关着法。

也就是说，输入重放阶段实际上在做：

1. 生成当前所有合法着法；
2. 再排除你自己实现的禁手/重复局面；
3. 检查平台传入的历史着法是否在这个集合里。

问题是：**历史着法已经被 Botzone 裁判接受过了。你重放历史时，不应该再用自己不完全可靠的禁手实现去否定它。**

尤其你的 `repeatAfterMove()` 是自己写的简化逻辑：

```cpp
return repeatTime >= 3;
```

它只根据无吃子后的同方局面重复次数判断，而中国象棋平台规则里长将、长捉、自然限着等细节可能和你的实现不完全一致。 一旦你的本地禁手判断和平台裁判判断不一致，就会出现：

> 平台认为这步历史着法合法，所以传给你；
> 你的程序认为这步历史着法不合法，于是抛异常；
> 程序未输出 JSON；
> Botzone 判你本轮输出非法。

因此，**输入阶段建议只做基础走法合法性检查，不要做 `WithForbidden` 检查。**
输出阶段仍然应该尽量用 `generateMovesWithForbidden()`，避免自己主动走出禁手。

## 3. `currBotColor` 确实没有被充分利用

你现在的代码计算了：

```cpp
colorType currBotColor =
    input["requests"][(Json::Value::UInt)0]["source"].asString() == "-1" ? RED : BLACK;
```

但是后面完全没有使用它。

这不一定直接导致非法，因为你的棋盘 `currColor` 会随着 `makeMoveAssumeLegal()` 自动红黑交替；该函数会要求源格是当前行动方棋子，并在走完后执行 `currColor = oppColor()`。

但 `currBotColor` 不使用会损失一个非常重要的检查：**重放完历史后，当前该走棋的一方应该正好等于本 Bot 的颜色。**

如果你是红方，重放完成后 `chess.currColor` 应该是 `RED`；如果你是黑方，重放完成后 `chess.currColor` 应该是 `BLACK`。如果不一致，说明历史重放顺序、坐标解析、空着处理、或前面某一步更新状态出错。

所以 `currBotColor` 应该至少用于这个断言：

```cpp
if (chess.getCurrColor() != currBotColor) {
    // 状态恢复错误
}
```

由于 `currColor` 是 `Chess` 的私有成员，需要给 `Chess` 加 getter。

# 建议修改一：给 `Chess` 增加状态读取接口

**修改位置：`class Chess` 的 `public:` 区域，建议放在 `Chess();` 后面。**

原来 `currColor`、`currTurnId` 是私有成员，外部无法检查。加两个只读接口：

```cpp
class Chess
{
    friend class ChessAI;
    friend class EvalRecord; 
private:
    std::vector<std::vector<Grid>> state;
    int currTurnId;
    colorType currColor;
    vector<int> continuePeaceTurn;
    vector<int> lastMoveEaten;

public:
    Chess();

    colorType getCurrColor() const { return currColor; }
    int getCurrTurnId() const { return currTurnId; }

    void resetBoard();
    // 后面保持不变
};
```

这样 `getInputBotzone()` 可以在重放结束后检查当前行动方是否就是本 Bot。

# 建议修改二：把 `getInputBotzone()` 改成“返回 bool，不抛异常”

**修改位置 1：函数声明处。**

把原来的：

```cpp
void getInputBotzone(Chess &chess);
void giveOutputBotzone(Chess &chess);
```

改成：

```cpp
bool getInputBotzone(Chess &chess, colorType &botColor);
void giveOutputBotzone(Chess &chess);
void outputFallbackBotzone(Chess *chess);
```

**修改位置 2：在 `writeMoveToJson()` 后面加入兜底输出函数。**

这个函数的作用是：如果 AI 搜索阶段出错，但棋盘已经恢复成功，就尽量输出一步合法随机/兜底着法；如果连棋盘状态都不可信，就输出 `-1`。

```cpp
void outputFallbackBotzone(Chess *chess)
{
    Json::Value ret;

    if (chess != nullptr)
    {
        vector<Move> moves;

        try
        {
            chess->generateMovesWithForbidden(moves, true);
        }
        catch (...)
        {
            moves.clear();
        }

        // 如果禁手版生成失败，退一步用基础合法着法，至少避免空输出。
        if (moves.empty())
        {
            try
            {
                chess->generateMoves(moves, true);
            }
            catch (...)
            {
                moves.clear();
            }
        }

        if (!moves.empty())
        {
            Move m = moves[0];
            writeMoveToJson(ret, m);

            Json::FastWriter writer;
            cout << writer.write(ret) << endl;
            return;
        }
    }

    // 实在无法恢复状态时，只能认输/无着。
    ret["response"]["source"] = string("-1");
    ret["response"]["target"] = string("-1");

    Json::FastWriter writer;
    cout << writer.write(ret) << endl;
}
```

注意：调试信息一定写到 `std::cerr`，不要写到 `cout`。Botzone 会把 `stdout` 当作 Bot 输出 JSON 解析，`cout` 里混入调试文本也会造成非法输出。

# 建议修改三：替换 `main()`，捕获所有异常

**修改位置：替换原来的 `main()`。**

```cpp
int main()
{
    Chess chess;
    bool boardReady = false;

    try
    {
        InitZobrist();

        colorType botColor = EMPTY;

        if (!getInputBotzone(chess, botColor))
        {
            std::cerr << "[FATAL] failed to parse/replay Botzone input" << std::endl;
            outputFallbackBotzone(nullptr);
            return 0;
        }

        boardReady = true;

        giveOutputBotzone(chess);
        return 0;
    }
    catch (const std::exception &e)
    {
        std::cerr << "[FATAL] uncaught exception: " << e.what() << std::endl;
        outputFallbackBotzone(boardReady ? &chess : nullptr);
        return 0;
    }
    catch (...)
    {
        std::cerr << "[FATAL] unknown uncaught exception" << std::endl;
        outputFallbackBotzone(boardReady ? &chess : nullptr);
        return 0;
    }
}
```

这样至少能避免“未捕获异常导致进程直接退出、Botzone 收不到 JSON”的情况。

# 建议修改四：重写 `getInputBotzone()`，输入重放只用基础合法性检查

**修改位置：替换原来的 `getInputBotzone()` 整个函数。**

下面这个版本做了几件事：

1. 检查 JSON 是否解析成功；
2. 检查 `requests/responses` 是否存在且为数组；
3. 使用 `currBotColor`；
4. 重放历史时用 `isMoveValid()`，不用 `isMoveValidWithForbidden()`；
5. 每一步失败时写 `stderr`，但不直接 `throw`；
6. 重放结束后验证 `chess.getCurrColor() == botColor`。

```cpp
static const char* colorToString(colorType c)
{
    if (c == RED) return "RED";
    if (c == BLACK) return "BLACK";
    return "EMPTY";
}

static bool isNullMoveString(const string &source, const string &target)
{
    return source == "-1" || target == "-1";
}

static bool isCoordString(const string &s)
{
    return s.size() == 2 &&
           s[0] >= 'a' && s[0] <= 'i' &&
           s[1] >= '0' && s[1] <= '9';
}

static bool getMoveFields(
    const Json::Value &node,
    string &source,
    string &target,
    const string &where
)
{
    if (!node.isObject())
    {
        std::cerr << "[INPUT] " << where << " is not an object" << std::endl;
        return false;
    }

    if (!node.isMember("source") || !node.isMember("target"))
    {
        std::cerr << "[INPUT] " << where << " missing source/target" << std::endl;
        return false;
    }

    if (!node["source"].isString() || !node["target"].isString())
    {
        std::cerr << "[INPUT] " << where << " source/target should be string" << std::endl;
        return false;
    }

    source = node["source"].asString();
    target = node["target"].asString();
    return true;
}

static bool applyExternalMove(
    Chess &chess,
    const string &source,
    const string &target,
    const string &where
)
{
    // Botzone 首回合红方 request 是 -1；如果后续出现 -1，也不要让 Move("-1","-1") 访问非法字符。
    if (isNullMoveString(source, target))
    {
        return true;
    }

    if (!isCoordString(source) || !isCoordString(target))
    {
        std::cerr << "[INPUT] bad coordinate at " << where
                  << ": " << source << " -> " << target << std::endl;
        return false;
    }

    Move curMove(source, target);

    try
    {
        // 关键修改：
        // 输入重放只验证基础合法性，不使用 isMoveValidWithForbidden。
        // 历史步已经被平台接受，不能再被本地 repeatAfterMove 误杀。
        if (!chess.isMoveValid(curMove, true))
        {
            std::cerr << "[INPUT] illegal basic move at " << where
                      << ": " << source << " -> " << target
                      << ", turnId=" << chess.getCurrTurnId()
                      << ", currColor=" << colorToString(chess.getCurrColor())
                      << std::endl;
            return false;
        }

        if (!chess.makeMoveAssumeLegal(curMove))
        {
            std::cerr << "[INPUT] makeMoveAssumeLegal failed at " << where
                      << ": " << source << " -> " << target
                      << ", turnId=" << chess.getCurrTurnId()
                      << ", currColor=" << colorToString(chess.getCurrColor())
                      << std::endl;
            return false;
        }
    }
    catch (const std::exception &e)
    {
        std::cerr << "[INPUT] exception at " << where
                  << ": " << source << " -> " << target
                  << ", what=" << e.what() << std::endl;
        return false;
    }

    return true;
}

bool getInputBotzone(Chess &chess, colorType &botColor)
{
    string str;
    if (!getline(cin, str))
    {
        std::cerr << "[INPUT] failed to getline from stdin" << std::endl;
        return false;
    }

    Json::Reader reader;
    Json::Value input;

    if (!reader.parse(str, input))
    {
        std::cerr << "[INPUT] JSON parse failed" << std::endl;
        return false;
    }

    if (!input.isMember("requests") || !input["requests"].isArray())
    {
        std::cerr << "[INPUT] missing requests array" << std::endl;
        return false;
    }

    if (!input.isMember("responses") || !input["responses"].isArray())
    {
        std::cerr << "[INPUT] missing responses array" << std::endl;
        return false;
    }

    const Json::Value &requests = input["requests"];
    const Json::Value &responses = input["responses"];

    int turnID = static_cast<int>(responses.size());

    if (requests.size() < static_cast<Json::Value::ArrayIndex>(turnID + 1))
    {
        std::cerr << "[INPUT] requests size is too small: requests="
                  << requests.size() << ", responses=" << responses.size()
                  << std::endl;
        return false;
    }

    string firstSource, firstTarget;
    if (!getMoveFields(requests[(Json::Value::ArrayIndex)0],
                       firstSource,
                       firstTarget,
                       "requests[0]"))
    {
        return false;
    }

    // 第一条 request 为 -1，说明本 Bot 是红方；否则本 Bot 是黑方。
    botColor = (firstSource == "-1") ? RED : BLACK;

    string curSource, curTarget;

    for (int i = 0; i < turnID; ++i)
    {
        string whereReq = string("requests[") + to_string(i) + "]";
        if (!getMoveFields(requests[(Json::Value::ArrayIndex)i],
                           curSource,
                           curTarget,
                           whereReq))
        {
            return false;
        }

        if (!applyExternalMove(chess, curSource, curTarget, whereReq))
        {
            return false;
        }

        string whereResp = string("responses[") + to_string(i) + "]";
        if (!getMoveFields(responses[(Json::Value::ArrayIndex)i],
                           curSource,
                           curTarget,
                           whereResp))
        {
            return false;
        }

        if (!applyExternalMove(chess, curSource, curTarget, whereResp))
        {
            return false;
        }
    }

    string whereCur = string("requests[") + to_string(turnID) + "]";
    if (!getMoveFields(requests[(Json::Value::ArrayIndex)turnID],
                       curSource,
                       curTarget,
                       whereCur))
    {
        return false;
    }

    if (!applyExternalMove(chess, curSource, curTarget, whereCur))
    {
        return false;
    }

    // 关键：真正使用 currBotColor/botColor。
    // 恢复完历史后，当前行动方必须是本 Bot。
    if (chess.getCurrColor() != botColor)
    {
        std::cerr << "[INPUT] side mismatch after replay. expected="
                  << colorToString(botColor)
                  << ", actual=" << colorToString(chess.getCurrColor())
                  << ", turnId=" << chess.getCurrTurnId()
                  << std::endl;
        return false;
    }

    return true;
}
```

这个改法可以直接解决你问的两个点：

第一，`currBotColor` 不再是“算了但不用”，而是成为重放正确性的最终检查。

第二，输入阶段不再因为你自己的 `repeatAfterMove()` 与平台规则不一致而直接抛异常退出。

# 建议修改五：修复搜索中的空步状态回撤问题

你已经写了 `NullMoveGuard`：

```cpp
struct NullMoveGuard{
    ChessAI* ai;
    NullMoveGuard(ChessAI* a) : ai(a) {ai->board->makeNullMove();}
    ~NullMoveGuard() {ai->board->undoMove(); }
};
```

这是正确方向。

但你在 `alpha_beta_search()` 里同时做了两次空步：

```cpp
this->MoveNodeVoid();

{
    NullMoveGuard tmpguard(this);
    null_val = -alpha_beta_PVS_search(...);
}
this->board->undoNullMove();
```

这等于：

1. 手动空步一次；
2. `NullMoveGuard` 构造时又空步一次；
3. 作用域结束自动撤销一次；
4. 手动再撤销一次。

正常情况下数量刚好抵消，但如果递归中抛出 `TimeOutException`，外层手动 `undoNullMove()` 可能执行不到，棋盘状态就会残留空步。

把 `alpha_beta_search()` 中这段：

```cpp
this->MoveNodeVoid();

int null_val;
{
    NullMoveGuard tmpguard(this);
    null_val = -alpha_beta_PVS_search(depth - 1 - R, -beta, -beta + 1);
}
this->board->undoNullMove();

if (null_val >= beta) {
    return beta;
}
```

改成：

```cpp
int null_val;
{
    NullMoveGuard guard(this);
    null_val = -alpha_beta_PVS_search(depth - 1 - R, -beta, -beta + 1);
}

if (null_val >= beta) {
    return beta;
}
```

同理，把 `alpha_beta_PVS_search()` 里的空步裁剪：

```cpp
this->MoveNodeVoid();

int null_val = -alpha_beta_PVS_search(depth - 1 - R, -beta, -beta + 1);

this->board->undoNullMove();

if (null_val >= beta) {
    return beta;
}
```

改成：

```cpp
int null_val;
{
    NullMoveGuard guard(this);
    null_val = -alpha_beta_PVS_search(depth - 1 - R, -beta, -beta + 1);
}

if (null_val >= beta) {
    return beta;
}
```

这个修改不一定是本次 `INVALID_INPUT_VERDICT` 的直接原因，因为 `giveOutputBotzone()` 最后还会用原棋盘校验 AI 选择的着法；但它会显著减少搜索棋盘状态错乱、超时后残留状态、根节点评分异常等问题。

# 建议修改六：评估状态 `GridControl/havecontrol` 应该在 `calstate()` 中刷新

你的 `EvalRecord` 里维护了：

```cpp
int GridControl[2][90];
bool havecontrol[90];
```

并且注释说明 `getGridcontrol()` 是用来填充控制点字典的。

但是当前 `calstate()` 直接调用：

```cpp
res += this->calstaticstate(target,color);
res += this->caldynamicstate(target,color);
```

没有先调用 `getGridcontrol()`。

而 `calstaticstate()` 中会调用 `hasattackchance()`，`caldynamicstate()` 会使用 `GridControl`。如果不刷新，评估就会使用旧控制表或全零控制表，导致搜索更依赖 MVV/LVA 吃子排序，而不是局面真实控制力。

建议把 `calstate()` 改成：

```cpp
int EvalRecord::calstate(vector<Grid>& target, colorType color)
{
    if (this->board == nullptr)
    {
        throw std::runtime_error("(calstate) board is null");
    }

    // 当前程序绝大多数 calstate 调用传入的是 board->state[currTurnId]。
    // 因此在这里刷新控制表，避免 GridControl/havecontrol 使用旧值。
    this->getGridcontrol();

    int res = 0;
    res += this->calstaticstate(target, color);
    res += this->caldynamicstate(target, color);

    colorType oppCol = (color == RED) ? BLACK : RED;
    int myShapePenalty = this->calShapePenalty(target, color);
    int oppShapePenalty = this->calShapePenalty(target, oppCol);
    res = res - myShapePenalty + oppShapePenalty;

    return res;
}
```

这个不是“非法输入”的直接修复，但它会改善搜索稳定性，减少开局阶段盲目吃子的倾向。

# 总结：这次问题最应该优先修的三处

最优先的是：

```cpp
getInputBotzone()
```

不要在输入重放阶段使用 `isMoveValidWithForbidden()`，改成 `isMoveValid()`。历史步已经被平台接受，重放阶段应该尽量复原局面，而不是用本地禁手实现重新审判平台历史。

第二优先是：

```cpp
main()
```

必须捕获异常并保证无论如何只向 `stdout` 输出 JSON。调试信息全部写 `stderr`。

第三优先是：

```cpp
currBotColor
```

计算出来后要用它检查：

```cpp
chess.getCurrColor() == currBotColor
```

这样你能第一时间发现“我以为现在轮到我，其实本地状态轮到对方”的状态错位问题。
