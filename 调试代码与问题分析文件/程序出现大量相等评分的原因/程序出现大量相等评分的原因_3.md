这并非你的棋盘状态未更新，也 **不是棋盘状态被污染** 。这其实是传统象棋引擎开发中非常经典的一个现象。

出现大量“着法不同但得分完全相同”的直接原因，在于你的 Alpha-Beta 搜索采用了“硬失败”（Fail-Hard）机制，且根节点的处理逻辑存在漏洞。

以下是为你深度剖析的问题成因以及修复方案：

### 1. 为什么会出现大量相同得分？

在你的根节点搜索函数 `alpha_beta_PVS_select` 中，代码是这样执行的：

**C++**

```
int alpha = minstateval;
int beta = maxstateval;

for(auto& Node : selected){
    // ...
    int score = -alpha_beta_PVS_search(d - 1, -beta, -alpha);
    Node.value = score;
  
    if(Node.value > alpha){
        alpha = Node.value;
    }
}
```

1. **确立基准分：** 假设第一个着法（或者当前搜到的最好着法）返回了得分 `150`。此时根节点的 `alpha` 更新为 `150`。
2. **搜索后续着法：** 对于随后的着法，程序调用子节点时传入的窗口是 `(-beta, -alpha)`，也就是 `(-999999, -150)`。
3. **子节点触发截断：** 子节点在进行评估或搜索时，如果发现当前局面得分（比如 `-100`）大于等于传进来的 `beta`（`-150`），就会触发  **Beta 剪枝** 。
4. **硬失败（Fail-Hard）的数学表现：** 我们来看看你 `alpha_beta_PVS_search` 以及其他搜索函数里触发剪枝的代码：
   **C++**

   ```
   if(val >= beta){ 
       RecordHash(curkey,depth,beta,BETA,node.strategy);
       return beta; // ！！！问题在这里！！！
   }
   ```

   **你直接返回了 `beta`（即 `-150`），而不是实际算出的评估值 `val`（`-100`）。**
5. **同分诞生：** 子节点返回 `-150`，根节点通过 `score = -(-150)` 算出来的得分就是 `150`。

**结论：** 任何只要**比当前最佳着法差**的着法（即劣败步，Fail-Low），都会直接触发剪枝并原封不动地返回当前的 `alpha` 值。这就导致大量明明很差的步法，最终显示的得分和最佳步法一模一样（都是 `150`）。

---

### 2. 程序在哪里出现了错误？

这个机制本身是符合 Fail-Hard 理论的，但结合你的根节点排序逻辑，就变成了一个 **致命的 Bug** ：

**C++**

```
Node.value = score; // 真正的劣败步也被赋予了和最佳步一样的最高分（如 150）
// ...
sort(selected.begin(), selected.end(), MoveNodecmp); 
```

因为大量“劣败着法”和“真正的最佳着法”获得了完全相同的得分，而 `std::sort` 是 **不稳定排序** ，它极有可能会在同分的情况下，把真正的最佳步挤出 `index 0` 的位置！

这会导致两个严重后果：

1. **迭代加深被破坏：** 下一层搜索时，排在最前面的已经不是真正的最佳步了，PVS 的零窗口探路将完全失效，搜索效率暴跌。
2. **容易走错棋：** 如果刚好遇到超时（TimeOut），程序截断并取 `selected[0]` 作为最终走法，此时 `selected[0]` 可能是一步送吃的劣败步（因为它窃取了最佳步的得分）。

---

### 3. 如何修复？

有两种修复思路，建议**同时采用**以保证程序的健壮性：

#### 修复方案一：将“硬失败”改为“软失败”（Fail-Soft） —— 强烈推荐

现代象棋引擎基本都使用“软失败”机制，即 **剪枝或搜索失败时，返回实际搜索到的最大值，而不是直接返回边界值** 。这能让根节点获得着法之间真实的优劣差距。

修改你的所有搜索函数（`alpha_beta_search`、`alpha_beta_PVS_search`、`quiescence_search`）：

增加一个 `best_val` 变量。

**C++**

```
int alpha_beta_PVS_search(int depth, int alpha, int beta) {
    // ...
    int best_val = -999999; // 记录本节点的实际最大值
    // ...
    for(auto& node : tmpMoveNodes){
        // ...
        val = -alpha_beta_PVS_search(...);
      
        if (val > best_val) {
            best_val = val;
            best_move = node.strategy;
        }

        if(val >= beta){ // beta剪枝
            RecordHash(curkey, depth, val, BETA, node.strategy); // 存入真实值
            return val; // 【修改处】：不要 return beta，而是 return 实际越界的 val
        }
      
        if(val > alpha){ 
            alpha = val;
            foundPV = true;
        }
    }
  
    HashFlag flag = (best_val > original_alpha) ? EXACT : ALPHA;
    RecordHash(curkey, depth, best_val, flag, best_move);

    return best_val; // 【修改处】：不要 return alpha，而是 return 实际找到的最大值 best_val
}
```

#### 修复方案二：根节点使用稳定排序

为了防止真正的最佳着法被同分的着法挤掉，请把 `alpha_beta_select` 及其它包含排序的地方，从 `sort` 替换为稳定的 `stable_sort`。

**C++**

```
// 将这一行：
sort(selected.begin(), selected.end(), MoveNodecmp);

// 替换为：
#include <algorithm>
std::stable_sort(selected.begin(), selected.end(), MoveNodecmp);
```

由于你在搜索前已经排过序，`stable_sort` 会保证如果后面遇到了得分相同的着法，原先排在前面的（真最佳步）依然会在前面，不会被劣败步顶替掉。
